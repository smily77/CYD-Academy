# 🎮 CYD Arcade Games

Vollständige Sammlung klassischer Arcade-Spiele für das CYD Display - verfügbar in **Retro** und **Modern** Versionen!

## 🎯 Übersicht

Diese Sammlung enthält 7 klassische Arcade-Spiele, jeweils in 2 Versionen:
- **Retro (12-18):** Klassisches Design mit einfachen Farben und Retro-Feeling
- **Modern (12b-18b):** Moderne Effekte mit Gradienten, Glow, Partikeln und 3D-Rendering

Plus 2 Touch-basierte Menü-Programme für einfachen Zugriff auf alle Spiele!

## 🕹️ Spiel-Details

### 12 / 12b - Pong

**Retro:**
- Klassisches schwarz-weiß Design
- 2-Spieler mit Potentiometer-Steuerung
- Auto-Modus für linken Spieler (AI)
- Einfache Rechteck-Grafik

**Modern:**
- Neon-Farben (Cyan, Pink, Grün, Gelb)
- Gradient-Hintergrund
- Ball-Trail-Effekt
- Partikel bei Kollisionen
- Pulsierender Glow-Effekt auf Paddeln
- 3D-Schatten

**Steuerung:**
- **Mit Potis:** 2x Potentiometer für Paddle-Bewegung, Button C/B für Auto-Modus, Button A für Score-Reset, Button D zurück zum Menü

- **Mit Encoder:** Encoder-Rotation für rechten Paddle, linker Paddle im Auto-Modus (kein Menü-Rückkehr)

## 🎨 Retro vs Modern - Feature-Vergleich

| Feature | Retro | Modern |
|---------|-------|--------|
| **Design** | Klassisch einfach | Moderne Effekte |
| **Farben** | Basic Palette | Neon & Gradienten |
| **Hintergrund** | Einfarbig | Gradient (Lila/Blau/Space) |
| **Objekte** | Einfache Formen | 3D-Rendering |
| **Effekte** | Keine | Glow, Partikel, Trails |
| **Performance** | Sehr schnell | Schnell (optimiert) |
| **Code-Größe** | Klein (~400 Zeilen) | Mittel (~700-1000 Zeilen) |
| **Speicher** | Minimal | Moderat |

**Retro-Versionen:**
- ✓ Perfekt für Nostalgiker
- ✓ Optimale Performance
- ✓ Minimaler Speicherbedarf
- ✓ Original Arcade-Feeling

**Modern-Versionen:**
- ✓ Beeindruckende Grafik
- ✓ Moderne Effekte
- ✓ Immer noch performant
- ✓ Zeigt Hardware-Potenzial

## 📚 CYD_Games Library

Alle Spiele sind in der `CYD_Games` Library als wiederverwendbare Klassen gekapselt:

**Retro-Klassen:**
- `PongGame.h`
- `SnakeGame.h`
- `BreakoutGame.h`
- `SpaceInvadersGame.h`
- `AsteroidsGame.h`
- `FroggerGame.h`
- `TetrisGame.h`

**Modern-Klassen:**
- `PongGameModern.h`
- `SnakeGameModern.h`
- `BreakoutGameModern.h`
- `SpaceInvadersGameModern.h`
- `AsteroidsGameModern.h`
- `FroggerGameModern.h`
- `TetrisGameModern.h`

### Verwendung

**Einfaches Beispiel:**
```cpp
#include <CYD_Display_Config.h>
#include <SnakeGame.h>  // Oder SnakeGameModern.h

LGFX lcd;
SnakeGame game;

void setup() {
  lcd.init();
  lcd.setRotation(1);
  game.init(&lcd);
}

void loop() {
  game.update();

  if (game.isGameOver()) {
    delay(2000);
    game.init(&lcd);  // Neustart
  }
}
```

**API für alle Spiele:**
- `void init(LGFX* display)` - Spiel initialisieren
- `void update()` - Game-Loop (einmal pro Frame aufrufen)
- `bool isGameOver()` - Prüft ob Game Over
- `int getScore()` - Aktueller Score
- `int getLevel()` - Aktuelles Level (bei manchen Spielen)
- `int getLives()` - Verbleibende Leben (bei manchen Spielen)

## 🔧 Hardware-Anforderungen

### Minimal (für alle Spiele):
- CYD Display (2.8" oder 3.5")
- ESP32 Board
- 4x Buttons (GPIO oder I2C über PCF8574)

### Hardware-Konfiguration

Die Spiele unterstützen flexible Hardware-Konfiguration über `CYD_Display_Config.h`:

**Option 1: GPIO-Buttons (direkt am ESP32)**
```cpp
#define gpioSwitch
#define tasteA 17
#define tasteB 5
#define tasteC 16
#define tasteD 18
```

**Option 2: I2C-Buttons (über PCF8574 Portextender)**
```cpp
#define i2cSwitch
#define tasteA 0        // PCF8574 Pin 0
#define tasteB 1        // PCF8574 Pin 1
#define tasteC 2        // PCF8574 Pin 2
#define tasteD 3        // PCF8574 Pin 3
#define pcfAddress 0x20
#define switchInterrupt 22  // Optional
```

**Option 3: GPIO-Encoder (Rotary Encoder direkt am ESP32)**
```cpp
#define gpioEnc
#define encA 17         // Encoder Pin A
#define encB 5          // Encoder Pin B
#define encSW 16        // Encoder Button
```

**Option 4: I2C-Encoder (Rotary Encoder über PCF8574)**
```cpp
#define i2cEnc
#define encA 0          // PCF8574 Pin 0
#define encB 1          // PCF8574 Pin 1
#define encSW 2         // PCF8574 Pin 2
#define pcfAddress 0x20
```

**Option 5-7: ESP-NOW (Drahtlose Eingabe über zweites ESP32)**
```cpp
#define espNowSwitch    // Drahtlose Buttons
// ODER
#define espNowEnc       // Drahtloser Encoder
// ODER
#define espNowPoti      // Drahtlose Potentiometer
```

**Potentiometer (optional für Pong & Breakout)**
```cpp
#define gpioPoti
#define potiLeft 34
#define potiRight 35
```

**Optional:**
- RGB LED (für visuelles Feedback)

**Wichtig:**
- Genau EINE von `gpioSwitch`, `i2cSwitch`, `gpioEnc`, `i2cEnc`, `espNowSwitch`, `espNowEnc`, `espNowPoti` muss definiert sein
- Pong und Breakout benötigen Potentiometer (`gpioPoti` oder `espNowPoti` muss definiert sein), außer mit Encoder
- Mit Encoder sind nicht alle Spiele kompatibel:
  - ✓ Kompatibel: Pong (AI-Modus), Breakout, Space Invaders, Frogger, Tetris
  - ✗ Nicht kompatibel: Snake, Asteroids (werden automatisch ausgeblendet)
- Alle anderen Spiele funktionieren nur mit Buttons (GPIO oder I2C)
- Bei I2C-Buttons/Encoder muss die PCF8574 Library installiert sein
- Bei ESP-NOW: Siehe [../examples/ESP-NOW_Sender/](../examples/ESP-NOW_Sender/) für Sender-Sketches und Pairing-Anleitung

## 🏆 High Score Tipps

**Snake:**
- Plane deine Route im Voraus
- Nutze die Wände nicht zu früh
- Vermeide lange gerade Linien

**Pong:**
- Treffe den Ball am Rand für steilere Winkel
- Nutze den Auto-Modus zum Üben

**Breakout:**
- Ziele auf die oberen Reihen (mehr Punkte)
- Nutze die Ecken für Trick-Shots

**Space Invaders:**
- Bleib hinter den Schilden
- Zerstöre die unteren Reihen zuerst
- Timing ist alles!

**Asteroids:**
- Große Asteroids = wenig Punkte, aber spawnen mittlere
- Kleine Asteroids = viele Punkte!
- Nutze Screen-Wrapping zum Entkommen

**Frogger:**
- Plane deine Sprünge
- Beobachte die Log-Geschwindigkeiten
- Nutze die vorderen Häuser zuerst

**Tetris:**
- Halte die Mitte frei
- Spare Long-Pieces (I) für 4er-Lines
- Nutze Ghost-Piece (Modern) zur Planung

## 🐛 Bekannte Limitierungen

- **Speicher:** Bei allen Spielen gleichzeitig geladen kann der ESP32 Speicher knapp werden
  - **Lösung:** Nutze die Menü-Programme, die Spiele einzeln laden
- **Performance:** Modern-Versionen benötigen mehr CPU
  - **Lösung:** Retro-Versionen verwenden wenn Performance wichtig ist
- **Tetris Rotation:** Manueller Rotation-Wechsel nötig wenn ohne Menü gestartet
  - **Lösung:** Nutze die Menü-Programme für automatischen Wechsel

## 💡 Tipps für Entwickler

**Eigene Spiele erstellen:**
1. Kopiere ein bestehendes Spiel als Vorlage
2. Folge dem Pattern: `init()`, `update()`, `isGameOver()`
3. Verwende Prefix für alle #defines (z.B. `MYGAME_`)
4. Teste auf beiden Display-Größen
5. Dokumentiere dein Spiel!

**Library erweitern:**
1. Erstelle Header-Datei in `libraries/CYD_Games/src/`
2. Verwende inline-Implementierung (keine .cpp Datei)
3. Forward declaration für LGFX
4. Alle Globals als Class-Members
5. Constructor mit Initializer-Liste
